# Triage media

An attachment matters when its contents can change where work belongs, its scope or price, approval, execution, or completion.

Inspect relevant files according to their type. View images and screenshots, transcribe or analyze audio, inspect only the needed parts of video, and extract text from documents. Use filenames, MIME types, context, and the original source ID or link to judge relevance.

Downloads are scratch files under `~/.cache/fulldev/work-triage/`. Keep media files under your home directory, not `/tmp`, because the PDF and image tools reject files there. WhatsApp media is already on disk at the path in the item. These local paths are not permanent references. Inspect the original when practical. Create a smaller derivative or selected frames when an analysis tool needs them. A derivative never replaces the original, and a small preview cannot prove details that are unreadable in it.

When media directly defines a requirement, decision, acceptance condition, blocker, handoff, or proof of completion, keep the full-resolution original. Add it, or a permanent URL to the original, to the right Company, Project, or Task `Resources` property according to `work-management`. Keep the original source reference in the Task Timeline when the file is Task evidence. Leave incidental media at its Gmail, Slack, WhatsApp, meeting, or file source when that source can be opened again.

Report a blocker when a needed file cannot be inspected or kept well enough to make the pending decision. An unavailable duplicate attachment does not block an outcome supported by other evidence.
