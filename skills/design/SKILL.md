# Design

Make the user's task clear and easy to complete. Follow the existing product, brand, design system, supplied design, and real content. Use the relevant Figma or component skills for tool instructions.

## Simplicity

- Give each screen or section a clear purpose and primary action. Use hierarchy, spacing, typography, and grouping before adding containers or decoration.
- Reuse established components and patterns. Add a variant or interaction only when the current task needs it; prefer fewer steps and choices over more explanation.
- Each element must help users understand, navigate, act, trust the product, or recognize its state. Remove unnecessary elements added during the task.
- Avoid decoration without a purpose: gradients, badges, small labels above headings, icon tiles, nested cards, oversized headings, repeated calls to action, and animation. Keep these when they are intentional parts of the supplied design or brand.
- Use concrete labels and truthful content. Do not invent testimonials, statistics, customer logos, functionality, or extra sections to fill a layout. Mockup placeholders must be recognizable as placeholders.

## Scope and review

Resolve the requested usability or visual problem. A small correction does not authorize a redesign, content rewrite, design system, or extra features. Suggest a broader change separately when it would help users complete the task.

Preserve keyboard access, readable contrast, labels, and useful empty, loading, or error states where relevant. Simplicity must not hide necessary information or functionality.

Inspect the result at the screen sizes and states affected by the change. Check alignment, spacing, text wrapping, hierarchy, and the primary action. Use the existing preview or output for review. Create a separate presentation or report only when requested.
