# Fixed-price work

For a substantial scope, group outcomes into categories with one customer price each. List the smaller deliverables under each category without their own prices. Give optional work its own price. For a small addition, one amount and a clear description of what is included is enough.

Include implementation, coordination, feedback, testing, and release in the deliverable. Put risk into the affected category instead of selling a generic contingency or feedback rounds. Explain assumptions that could change the price. Label real open dependencies `❓ Open punt` when useful.

Keep estimated effort, the rate, and the calculation internal. Customer scopes are in euros unless the user asks for hours. If the customer document and the internal calculation are separate, check that the category totals still match after a revision. End a customer scope at its total table unless the user asks for notes below it.

Use v1/v2 or separately priced options only when there is a real choice to make. Do not add a smaller variant to an agreed scope or postpone the larger one without support in the agreement.

For website scopes, use these terms:

- **layout**: a complete page or route;
- **block**: a pagebuilder or full-width content section;
- **component**: a smaller reusable interface or functional element.

Check the existing implementation when it affects the estimate. Price the remaining change, not a rebuild of something that already works.
